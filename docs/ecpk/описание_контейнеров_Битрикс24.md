# Описание контейнеров: портал 1С-Битрикс24

Источники:

- официальный репозиторий [bitrix-tools/env-docker](https://github.com/bitrix-tools/env-docker/);
- Helm-чарт Yandex Cloud `bitrix-env` 1.0.6 (`appVersion: 9.0.10`), сохранённый в [`charts/bitrix-env`](../../charts/bitrix-env/).

## Kubernetes

Helm-чарт требует Kubernetes `>=1.28.0-0`. Основной Deployment с Nginx и PHP-FPM масштабируется параметром `replicaCount` в `prod`-окружении.

| Компонент | Версия | Назначение |
|---|---|---|
| PHP-FPM | 8.2.30, 8.3.30, 8.4.19 | Исполнение портала |
| Nginx | 1.28.3-v1 | HTTP(S), статика, прокси на PHP-FPM |
| Redis | 8.6.2 | Опциональное хранилище кеша |
| Push Server | 3.2-v1 | Real-time уведомления |
| Sphinx | 2.2.11-v2 | Полнотекстовый поиск |
| PHP-FPM Exporter | 2.2.0 | Метрики PHP |
| Nginx Prometheus Exporter | 1.5.1 | Метрики Nginx |
| Cron | PHP-образ выбранной версии | Агенты и резервное копирование |
| MySQL/Percona | 8.0 и выше, внешний сервис | Основная СУБД; чарт её не разворачивает |

Внешние инфраструктурные зависимости: CSI-S3 и, опционально, cert-manager.

## Объектное хранилище

Helm-чарт использует Yandex Object Storage:

- вендор: Yandex Cloud;
- API: S3;
- endpoint: `https://storage.yandexcloud.net`;
- регион: `ru-central1`;
- StorageClass: `csi-s3`;
- общие каталоги: `upload` и `backup`.

## Docker Compose

`bitrix-tools/env-docker` остаётся отдельным dev/примером окружения. Оно оркестрируется Docker Compose и не содержит Kubernetes-манифестов. В нём дополнительно представлены PostgreSQL, Memcached, Lego/SSL и контейнер Percona Server; эти компоненты не входят в целевую архитектуру Helm-чарта.

## Базовые ОС образов (UBI)

- **Alpine** — основные Bitrix-образы в `env-docker`;
- **RHEL** — Percona Server в `env-docker`;
- **Debian (trixie)** — PostgreSQL в `env-docker`.

Для аттестации базовую ОС каждого стороннего образа Kubernetes следует подтвердить по его SBOM/manifest: Helm-чарт сам эту информацию не декларирует.

## Роль Transformer — без контейнеризации

В `env-docker` и Helm-чарте **нет** сервиса/образа для Transformer. Роль Document Converter контейнеризацию **не поддерживает**.

### Состав

| Часть | Что входит |
|---|---|
| Модули Битрикс24 | `transformer`, `transformercontroller` версии 20.100.0 и выше (редакция **Энтерпрайз**) |
| ОС-пакеты | Erlang, RabbitMQ Server, LibreOffice, FFmpeg |
| Конфиг | `/etc/bitrix-transformer.env` (RabbitMQ: host/port/user/password/vhost) |

### Зависимость от PHP

Серверная роль Transformer требует PHP и сайт Битрикс с модулем `transformercontroller`; автономно без PHP не работает. При этом клиентский модуль `transformer` и серверный `transformercontroller` разделены: сервер конвертации может по HTTP обслуживать другие сайты.

Ограничение вендора: не более одной роли Transformer на машину.

## Замечания для ЕЦПК

1. Официальный env-docker — **dev/пример** контейнерного окружения; для production вендор рекомендует дополнительный hardening.
2. Kubernetes-манифест: Helm-чарт Yandex Cloud 1.0.6; дополнительный формат — Docker Compose.
3. В Kubernetes используется Yandex Object Storage через CSI-S3; в env-docker объектное хранилище настраивается отдельно.
4. На хостах с ОС ФСТЭК (Astra Linux SE 1.8, Альт 10 СП) в README env-docker описан запуск Docker/Compose из репозиториев ОС.
5. Роль **Transformer** в контейнеры не выносится и не работает без PHP/сайта Битрикс.
